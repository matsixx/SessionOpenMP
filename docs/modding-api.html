SessionOpenMP Modding API

Send your mod's own data to the other players in a session.

Features

  • Named channels: only players with the same channel receive
  • Send to one player or everyone, reliable or not
  • Up to 1000 bytes per message
  • Join and leave events, so late joiners get your state
  • One agreed authority for shared state
  • Safe from any thread; callbacks on the game thread
  • Your mod still runs when OpenMP isn't installed
  • Works from UE4SS Lua mods, no DLL needed

Description

There is no Unreal network connection between players. Everyone runs their own single-player game and OpenMP draws the other skaters in, so replicated variables, RPCs and multicasts never reach anyone else.

This API gives your mod the connection players already have. OpenMP carries your bytes and never reads them. Players on a SessionOpenMP older than 1.1.12 never show up to your mod.

Lua mods get the same API with no header and no DLL; see 10. There is no Blueprint support yet.

1Connecting

Copy sdk/omp_mod_api.h into your project.

  • OmpMod_Bind finds OpenMP by its exports and fills the struct. It returns 0 when OpenMP isn't loaded, so your mod keeps working without it.
  • Channel names are 1–63 characters from A-Z a-z 0-9 _ . -. Start with your name so two mods never pick the same one.
  • Register works any time, in or out of a session. The handle stays valid across sessions and map changes until you call Unregister. Don't call it when the game closes: OpenMP may already be unloaded by then.

2Sending

omp.Send(channel, player, data, len, reliable); // 1 = queued, 0 = refused
  • player is OMPMOD_EVERYONE or one player's number.
  • Up to 1000 bytes. Put your own format version in the first byte, so you can change the format later.
  • reliable = 1 arrives, in order. reliable = 0 can be dropped; use it only for values you resend constantly.
  • Refused when you're not in a session, the message is too big, the handle is invalid, or you're over the limits in 4.

3Receiving

void OnMessage(int player, const uint8_t* data, int len, void* user);

data is only valid during the call, so copy what you keep.

Caution

Treat everything you receive as untrusted. Any player in the lobby can send any bytes on your channel, including a modified copy of your mod. Check len before reading, range-check every value, and never use a received number as an array index, size or pointer without checking it.

5Players

void OnPlayer(int player, int joined, void* user);
  • joined = 1: a player with your channel appeared, including everyone already there when you register. Send them your current state now.
  • joined = 0: they left, or unregistered the channel. PlayerId and PlayerName still return them here, so you can tell who it was.
Note

Player numbers are local to your game. The same person has a different number on every other machine, and a number can later belong to someone else. Never put a player number in a message; use PlayerId for anything you send or keep.

  • PlayerName is a label only: names can repeat, or be empty for a moment after someone joins.
  • PlayerActor is their skater in your world, or null when they aren't spawned or are on another map. Use actors on the game thread only, and look them up again each frame instead of keeping them.

6Shared state

There is no server. For anything everyone has to agree on, like a score or a round, one player decides: the authority. It's the player with the lowest player ID among everyone who has your channel. Every game works out the same answer without sending anything, and it moves on its own when that player leaves.

The pattern: other players send requests, the authority applies them and sends the full state, and everyone ignores state that doesn't come from Authority(channel). 9 is a complete example.

7Threads

  • Every function is safe to call from any thread.
  • Callbacks run on the game thread. Don't block in them. Sending from inside a callback is fine.
  • Call Unregister from the game thread. From another thread, a callback already in flight can still run once.

9Typical application

A shared round timer. The authority owns the countdown and everyone else shows it. If the authority leaves, the next one already has the latest state and carries on.

10Lua mods

Every UE4SS Lua mod gets a global OpenMP table, ready from the first line of main.lua. It's the same API with Lua types, and everything above applies: the limits in 4, untrusted data, local player numbers, and the authority.

  • Send(channel, player, data, reliable) takes any Lua string up to 1000 bytes. reliable defaults to true.
  • PlayerActor and ActorPlayer use UObjects and only work on the game thread: inside your callbacks, or in ExecuteInGameThread.
  • Callbacks run on the game thread, a frame or two after the message arrives. An error in one is printed to UE4SS.log as an [OpenMP] line and doesn't stop the others.
  • Lua and C++ mods can share a channel; bytes arrive exactly as sent. string.pack and string.unpack read and write the same layouts a C++ mod uses.

11Checking it works

SessionOpenMP.log in the game's Win64 folder has a [modapi] line for each registration, each player joining or leaving your channel, refused sends, and messages dropped over the limits. Lua callback errors show up in UE4SS.log.
